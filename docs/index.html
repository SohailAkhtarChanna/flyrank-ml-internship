Search Intelligence for Content Review: Combining CTR Opportunity Scoring with Decision Tree Signals

FlyRank ML Internship — Search Intelligence Capstone

Abstract

Search-intelligence teams need practical ways to identify content pages that deserve review without treating observed performance patterns as causal explanations of search rankings. This study asks which content-performance signals can help prioritize pages for search visibility and click-through opportunities using an anonymized FlyRank ML Internship dataset. I compare a transparent CTR-based baseline with a Decision Tree classifier trained using a client-grouped 80/20 split and a set of search, engagement, freshness, and content features. The Decision Tree achieved 69.79% accuracy on 6,163 held-out pages from seven unseen clients, but its macro F1 score was 0.49 and it failed to correctly classify the excellent impression tier. The results support a baseline-first, model-assisted, human-reviewed workflow in which CTR opportunity scoring identifies concrete review candidates while model signals provide additional directional context.

1. Introduction / Problem Statement

Search-intelligence teams need repeatable methods for deciding which content pages should receive attention first. A useful workflow should prioritize measurable opportunities while avoiding unsupported claims about search-engine ranking mechanisms.

The research question for this project is: Which content-performance signals can help identify pages that are worth reviewing for search visibility and click-through opportunities?

The decision supported by this analysis is how to prioritize pages for content and CTR review using observed search and engagement signals. The approach is designed as decision support rather than an automatic content-optimization or ranking system.

2. Data

The analysis uses the anonymized FlyRank ML Internship development dataset, containing 30,000 content records and 44 columns. The dataset includes search, content, engagement, freshness, and performance fields.

Feature groups

  • Search signals: search volume, competition, and CPC.
  • Content signals: word count and character count.
  • Freshness signals: content age and days since last update.
  • Search-performance signals: average position and CTR.
  • Engagement signals: engagement rate, scroll rate, and AI traffic percentage.
  • Target: impression_tier.

Evaluation data

30,000 Dataset records
44 Dataset columns
23,837 Training records
6,163 Test records

A client-grouped 80/20 split was used. The training set contains 23,837 records from 25 clients, while the held-out test set contains 6,163 records from seven unseen clients. There was zero client overlap between the training and test sets.

Missing feature values were handled using medians calculated from the training set only. The same training medians were then applied to the test set.

No client names, domains, private search queries, credentials, or raw client exports are included in this public-facing analysis.

3. Methodology

Model

The selected model is a Decision Tree Classifier with max_depth=5 and random_state=42. The model was selected because its decision structure is relatively interpretable and suitable for a decision-support workflow.

Features and target

The model uses 12 features:

search_volume, competition, cpc, word_count, char_count, content_age_days, days_since_last_update, avg_position, ctr, engagement_rate, scroll_rate, and ai_traffic_pct.

The target is impression_tier, consisting of four observed classes: low, moderate, good, and excellent.

Validation and leakage control

A client-grouped split was used so that content from the same client could not appear in both training and testing data. This reduces the risk of learning client-specific patterns. Client ID was not used as a predictive feature.

Test-set information was not used to calculate preprocessing statistics. Training-set medians were used for both training and testing data.

Baseline

The Week-4 baseline is a transparent CTR opportunity score. It prioritizes pages with meaningful search exposure and CTR below the average CTR for their search-position bucket.

The baseline uses four position buckets: 1-3, 4-10, 11-20, and 21+. Pages must have at least 100 impressions and a positive CTR gap.

The baseline score is:

log1p(impressions) × CTR gap

This is a review-prioritization rule rather than a classification model.

4. Results

69.79% Decision Tree accuracy
0.49 Macro F1
0% Excellent-tier recall
0% Top-20 overlap

The Decision Tree achieved 69.79% accuracy on the held-out test set. Performance was strongest for the low impression tier, with an F1 score of 0.84 and recall of 0.90.

Performance was weaker for the good and moderate tiers, and the model did not correctly classify any items in the excellent tier.

5. Limitations & Honest Framing

The results should be interpreted as directional decision support, not as proof of causal effects or Google's ranking factors.

Although the Decision Tree achieved 69.79% accuracy, its macro F1 score was 0.49 and it did not correctly classify any items in the excellent impression tier. Overall accuracy therefore does not mean that all impression tiers are predicted reliably.

The dataset is imbalanced across impression tiers, and the fitted tree relied heavily on CTR and engagement rate. Feature importance describes how the model used the available features in this specific training run; it does not establish that these variables cause better or worse search performance.

The baseline and model also produce different prioritization queues. Their Top-20 overlap was 0%, so the comparison is best understood as showing different decision-support perspectives rather than proving that one method is better.

The Decision Tree also produced tied model scores for several top-ranked items because pages reaching the same terminal tree leaf receive the same predicted class probabilities. The ranking should therefore be combined with transparent rules and human review.

6. Ranked Recommendations

Priority 1 — Review high-exposure, low-CTR pages

Start with pages identified by the CTR baseline: pages with at least 100 impressions and CTR below the average for their position bucket. Review titles, descriptions, search-intent alignment, SERP presentation, and content relevance before making changes.

Priority 2 — Validate pages with strong model signals

Use the Decision Tree as a secondary signal. CTR, engagement rate, days since last update, and average position were the most influential features in the fitted model. These signals can identify patterns worth investigating but should not be treated as causal ranking factors.

Priority 3 — Investigate ambiguous cases manually

The model struggled to distinguish the excellent tier and frequently confused neighboring good, moderate, and low classes. These cases should therefore be reviewed by a human rather than automatically assigned an action.

Priority 4 — Combine model evidence with contextual checks

Before recommending a content change, check factors not represented in the model, including search intent, SERP features, brand effects, content quality, and measurement issues.

Overall, the recommended workflow is: baseline-first, model-assisted, human-reviewed.

8. Reproducibility

The analysis is implemented in the FlyRank ML Internship repository and can be reproduced from the capstone notebook.

Main notebook: work/notebooks/capstone.ipynb

The workflow loads the anonymized development dataset, applies the documented feature selection and train-only median imputation, creates a client-grouped 80/20 split, trains the Decision Tree, evaluates its predictions, constructs the CTR baseline on the same held-out test set, and compares the resulting prioritization queues.

The notebook is designed to run from top to bottom so that data preparation, model training, evaluation, visualizations, baseline comparison, and recommendations can be reproduced in sequence.
